# 2026-09-23

## 删除接口安全加固（v0.4.2，改动只留在工作区）

- 背景：ComfyUI-Manager PR #3180 评审意见 —— `POST /prompt-warehouse/delete-output-images`
  只有 loopback 校验不够（用户浏览器里任何一个开着的页面，请求也来自本机）。要求：
  ① 用 realpath + commonpath 把目标锁死在 output 目录内，拒绝绝对路径与 `..`；
  ② 删除必须是用户真实发起 / 本地专属，或者干脆撤掉路由、把删除留在节点执行里。
- 选型：保留路由（方案 A，用户体验不变）+ 令牌握手；版本按补丁走 `v0.4.2`。
- `routes.py`：
  - 新增 `GET /prompt-warehouse/session` 下发进程内 `DELETE_TOKEN`（`secrets.token_urlsafe(32)`），
    该响应**绝不能加 CORS 头**；
  - 删除路由要求 `Content-Type: application/json`（否则 415）+ `X-Prompt-Warehouse-Token`
    校验（否则 403，附 `"code": "token"` 供前端区分过期令牌）；
  - `_safe_output_file` 改为 `realpath` + `commonpath`，逐项拒绝：绝对路径、盘符（含
    `C:foo` 这种 drive-relative）、`..`、文件名里的 `/` 与 `\`、NUL、目录、越界符号链接；
    批量上限 `MAX_DELETE_FILES = 100`。
- 关键事实（查过 ComfyUI master 的 `server.py`）：默认中间件 `create_origin_only_middleware`
  会拦 `Sec-Fetch-Site: cross-site` 和 Host/Origin 主机名不一致；但用户一旦加
  `--enable-cors-header` 就换成 `create_cors_middleware`，完全不做 Origin 校验，而它的
  `Access-Control-Allow-Headers` 固定为 `Content-Type, Authorization`。**自定义请求头过不了预检**
  正是这次防护的立足点。
- `web/save_image_with_delete.js`：令牌按需获取并缓存；收到 403 + `code: token`
  （ComfyUI 中途重启）时静默重取并重试一次。
- 测试：`tests/test_routes.py` 扩到 78 条断言（令牌缺失/错误、非 JSON、无 Content-Type、
  路径穿越矩阵、目录、符号链接逃逸、批量超限、空/畸形载荷），实际跑过符号链接用例；
  4 个脚本全绿。
- 文档：两个 README 的「接口安全限制」整节改写；`AGENTS.md` 新增 §4 item 7（删除路由硬约束）
  与 §6 第二条 review item，并注明「PR 评论暂缓」。
- 环境经验：`tests/test_save_metadata.py` 硬编码 `D:\ComfyUI-aki-v3\ComfyUI`，必须用
  `D:\ComfyUI-aki-v3\python\python.exe` 运行（需要 PIL / numpy / torch），裸 python 会
  `ModuleNotFoundError`。已写入 `AGENTS.md` §5。
